## お知らせを投稿する

1. [Shopifyのブログ記事](https://admin.shopify.com/store/km-nagoya-doll-r1yeax0z/content/articles)を開き、「ブログ記事を作成する」を選びます。
2. タイトルと本文を入力します。本文には見出し、画像、リンク、箇条書きなどを利用できます。
3. ブログを **お知らせ** にします。表示するカテゴリはタグに入力します（例：商品情報、催事、営業案内）。複数ある場合は先頭のタグを表示します。
4. 公開日時を設定して保存します。非公開の記事はサイトに表示されません。
5. [お知らせ一覧](https://hirojessica.github.io/kmrn/news.html)を再読み込みして確認します。トップページにも最新3件が自動で表示されます。

一覧は公開日時の新しい順、12件ずつの追加表示です。記事の編集・公開後にGitHubへ再アップロードする必要はありません。画像や投稿がAPIに反映されるまで短時間かかる場合は再読み込みしてください。

## 商品・お知らせの日本語と英語を編集する

1. 通常の **商品管理** または **コンテンツ → ブログ記事** では、日本語のタイトル・本文を入力して保存します。同じ本文欄に英訳を併記しません。
2. [Shopify Translate & Adapt](https://admin.shopify.com/store/km-nagoya-doll-r1yeax0z/apps/translate-and-adapt?shopLocale=en) を開き、対象言語を **英語** にします。
3. **商品管理** または **ブログ記事** を選び、対象の作品・記事を開きます。
4. 左の日本語を参照し、右の **タイトル - 英語** と **説明／コンテンツ** に英訳を入力して保存します。見出し・リンクの文字・写真の説明も英語側で編集できます。
5. 公開サイトの **EN** を選び、一覧と詳細を確認します。**JP** に戻すと日本語原稿が表示されます。選択は同じブラウザーでのページ移動・再読み込み後も保持されます。

商品・記事の各画面の **その他の操作 → ローカライズ** から翻訳編集へ進むこともできます。原文を変更した場合は、英訳も見直して保存してください。[Shopify公式の編集手順](https://help.shopify.com/en/manual/international/translate-adapt-app)も参照できます。

2026-09-05に英語を追加・公開し、テスト商品3点・記事2件のタイトルと本文を登録しました。既定の言語は日本語のままです。トップの新商品・お知らせ、各一覧、商品詳細、記事詳細は、既存のStorefront APIの言語指定で翻訳を取得します。新しい原稿を更新してもGitHubへの再アップロードは不要です。

英語訳が未登録の項目は [Shopifyの仕様](https://help.shopify.com/en/manual/international/localization-and-translation) により日本語原文へ戻ります。新規の作品・記事でも英語欄まで保存してください。文章が自動で翻訳される設定にはしていません。翻訳の編集・公開状態は **設定 → 言語** で確認できます。既存リンクを維持するため、今回URLハンドルの変更・翻訳は行っていません。

ギャラリーの翻訳は以下の既存の **英語タイトル・英語説明・英語カテゴリ** 欄を使用します。

## 写真を追加・差し替える

1. [フォトギャラリーの管理](https://admin.shopify.com/store/km-nagoya-doll-r1yeax0z/content/metaobjects/entries/gallery_item)を開きます。通常のメニューでは **コンテンツ → メタオブジェクト → フォトギャラリー** です。
2. 「エントリーを追加」を選び、**タイトル**を入力します。
3. **画像を選択**から、新しい画像をアップロードするか、Shopifyに保存済みの画像を選びます。
4. 必要に応じて**説明**と**カテゴリ**を入力します。
   英語ページに載せる文章は、同じ画面の**英語タイトル・英語説明・英語カテゴリ**に入力します。写真の説明を日本語で入れる場合は英語説明も入力してください。
5. ステータスを **Active** にして保存すると掲載されます。**Draft** にすると非公開です。
6. [フォトギャラリー](https://hirojessica.github.io/kmrn/gallery.html)を再読み込みします。

1エントリーが1枚の写真です。2026-09-06から、一覧は**1ページ10枚**で「前へ・ページ番号・次へ」によるページ送りに対応しています。表示順は引き続き更新順です。縦4:5の枠内に写真全体を収めるため、画像の縦横比が違ってもレイアウトが揃います。クリックすると拡大できます。2026-09-05に現行ギャラリーの18枚（作品10枚・制作工程7枚・歴史資料1枚）を登録しました。

### カテゴリで絞り込む

- 「すべて」と、公開エントリーの**カテゴリ**欄から作った選択ボタンを表示します。現在は「作品」「制作工程」「歴史資料」です。括弧内は各カテゴリの写真枚数です。
- カテゴリボタンは幅・高さをそろえて中央揃えにしています。PCは4列、880px以下は2列です。カテゴリが増えて次の行に折り返しても同じ大きさを保ち、長い英語のカテゴリ名はボタン内で折り返します。
- 同じカテゴリにまとめる写真は、カテゴリ欄を同じ表記にそろえてください。新しい名前を入力すれば、そのカテゴリも次回のページ読み込みで自動的に追加されます。未入力の写真は「未分類」にまとめます。
- 英語表示は**英語カテゴリ**欄を使います。同じカテゴリでは英語表記も統一してください。
- カテゴリを選び直すと1ページ目に戻ります。絞り込み後の写真も10枚ずつ表示し、1ページ以内ならページ送りを隠します。日英切り替えでは選択カテゴリとページを維持します。
- カテゴリとページ番号はURLに保存されるため、再読み込みやブラウザーの戻る・進むでも同じ一覧に戻れます。

カテゴリの抽出は全公開エントリーを対象にします。Shopifyの写真情報を100件ずつ最後まで読み取り、表示中の10枚だけ画像要素を作ります。途中の取得に失敗したときは不完全なカテゴリや総件数を表示せず、再読み込みボタンを案内します。大量登録時にはメタデータ全件の取得時間が増えるため、運用規模が大きくなった際は取得方式を再検討してください。

## お問い合わせ

- [お問い合わせページ](https://hirojessica.github.io/kmrn/contact.html)から **info@km-nagoya-doll.com** へ送ります。
- メール配信には[FormSubmit](https://formsubmit.co/)を使用します。GitHub Pagesだけではメール処理を実行できないため、フォームのPOSTを同サービスで受け付けます。
- 名前・メール・種類・本文・情報利用への同意が必須、会社名と電話は任意です。返信先には入力されたメールアドレスが使われます。
- CAPTCHAを有効のまま使用し、追加の迷惑送信対策欄も設置しています。送信時にはサービス側の確認画面を経由する場合があります。送信後は同じサイトの完了ページへ戻ります。
- 配信サービスの[個人情報の扱い](https://formsubmit.co/privacy.pdf)へのリンクをフォーム内に表示しています。

## 制作・検証

- 全9ページで共通の `partials/header.html`、`footer.html`、`menu.html` を使用。`python scripts/sync-chrome.py` で同期します。
- お知らせ、記事詳細、ギャラリーは `assets/content.js`。Shopifyの公開コンテンツだけをStorefront APIから取得します。`contentHtml` は許可する要素だけを再構築して表示します。
- 読み込みエラー・空の一覧・非公開記事を別々に扱います。追加読み込みの失敗時は既存データを保持します。
- HeadlessのAPI権限は商品読み取りに加え、`unauthenticated_read_content` と `unauthenticated_read_metaobjects`。顧客・注文の権限は追加していません。
- `node --test tests/storefront-api.test.mjs`：13件合格。固定ハンドルの参照、重複抑止、Draftと不正レスポンスの区別を含みます。
- `tests/content-ui.html`：記事HTML、ニュースの追加表示と再試行、ギャラリーの拡大表示・英語欄、商品写真枠とテスト購入制御、記事・商品名の日英往復、言語切替時の応答競合を含む27件合格。静的HTTPでrepoルートから配信して実行できます。公開フォルダには含めません。
- Shopifyの実APIで商品3件・ニュース2件のJA／ENを照合済み。ギャラリー18件は既存の翻訳欄を維持しています。
